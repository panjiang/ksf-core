# 最小任务检查点

检查点让另一会话能够从已保存的事实继续一项任务。它是项目中的普通 Markdown，由宿主 Agent 按授权保存和复核；没有专用 checkpoint 命令，聊天采集器也不自动生成检查点。程序读取成功只证明文件可读，不证明目标、授权和外部动作仍有效。

## 唯一位置与入口

已有主项目时，使用 `项目/<项目名>/任务/<任务名>.md`，文件名保持可读。一个任务维护一份现行检查点；根卡 `project.md` 只保存任务名称和链接，项目事实沿已有领域原文保存，已采用管理机制时现行安排由管理主件持有。检查点保存恢复摘要及原文入口，不复制工程正文、整段聊天或另一份项目进度表。

没有主项目的一次性任务继续使用会话上下文；用户要求保存时先确定已有项目或明确保存位置，不为格式完整自动建项目。多个未完成任务均列在根卡中，用户只说“继续”且不能唯一确定时先澄清，不凭修改时间选一个。

最小元数据如下。它是普通材料格式，不是第五类能力对象，也不使用对象 CLI 管理：

```yaml
---
checkpoint_schema: 1
task_id: "example-task-001"
name: "示例任务"
state: "in_progress"
updated: "2026-10-19T10:00:00+08:00"
---
```

task_id 是任务内稳定的非空标识，改文件名不改标识；示例值不能复制为多个真实任务的身份。state 使用 in_progress、paused、blocked、completed 或 cancelled，仅表达记录状态，不是程序自动执行的状态机。updated 写实际保存时间。遇到未知 schema，先保留原件并说明不支持，不猜测迁移或覆盖。

## 必须能够恢复的信息

正文可以按任务调整章节，但必须能回答以下问题；没有的内容明确写“无”或“未知”：

| 信息 | 最小内容 |
| --- | --- |
| 目标与完成条件 | 用户要得到什么、本次范围和关键约束；最新纠正覆盖哪些旧结论 |
| 项目与工作位置 | 根卡、当前 KSF 根、实际工程入口；跨设备绝对路径需重新核实 |
| 当前安排 | 正在做哪一步、已完成什么、未完成什么；采用对象的精确 id@version、实际来源和路径 |
| 已确认决定与授权 | 用户原始指令或可信来源入口、允许的动作及目标、适用条件和已消耗动作；记录不自行产生新授权 |
| 产物与证据 | 当前文件、回执、测试结果入口及其实际范围；易变化输入记录版本、摘要或核对方法 |
| 外部动作 | 已完成、未开始或结果未知；已发起动作保存操作 ID、实际回执及下一次对账方式 |
| 待决项与下一步 | 仍缺什么，第一项可执行动作及其前置条件；依赖缺口不阻止哪些独立工作 |

权限、凭据和完整私人资料不复制进检查点。已失效方案从当前安排中移除，必要时保留简短纠正依据和历史入口，不能继续作为下一步执行。

## 维护与恢复方法

业务维护、保存时机、先写检查点再补入口、多文件部分失败以及恢复顺序由[项目推进控制](../../abilities/competencies/project-control/competency.md#项目恢复暂停与检查点)唯一持有。通用授权、基线、并发与回退保障由[资产维护](../../abilities/competencies/asset-maintenance/competency.md)提供，runtime 只保持请求层连续性。本文件定义普通 Markdown 的位置、字段和可恢复信息，不另维护一套专业流程。

存在管理主件时，现行目标、阶段、承诺与事项状态以[项目管理契约](../project-management.md)为准；检查点保留具体执行细节和必要的稳定事项 ID 关联，不自动同步来源快照。旧项目缺管理主件仍可恢复，读取不自动创建。完成或取消记录是历史材料，不自动重开；记录中的权限声明不能替代当前有效授权。

项目已归档时保持原件并按相应 scope 调阅；明确恢复按项目基本功处理。没有已保存记录不能声称自动恢复。独立新会话和实际任务效果按[任务回归](task-regression.md)另行验证。
